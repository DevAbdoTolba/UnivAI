● Yes and yes.

  Fresh machine: git submodule update --init --recursive clones all four, at
  exact commits root repo points at.

  Already-have machine: same command, two-step dance:

  git pull
  git submodule update --init --recursive

  - git pull bring new root code + new submodule pointers.
  - git submodule update --init --recursive move submodules to match pointers.
  --init harmless when already done — only kicks in if tribe added brand-new
  submodule. So always run same command, no thinking needed.

  One-liner also exist: git pull --recurse-submodules — does both.

  Important cave law: this syncs submodules to commit root repo recorded, not to
  latest on teammate's branch. Teammate pushed fresh UnivAI-Agent code? Root
  pointer must move first:

  git submodule update --remote UnivAI-Agent   # grab branch tip (temp)
  git add UnivAI-Agent && git commit           # record new pointer, push

  Then rest of tribe git pull + submodule update and all see same code.

  One Makefile already branches on OS — sickness is two small bugs inside it:

  Bug 1: setup calls bare python -m venv .venv (Makefile:60). Ubuntu has no
  python — only python3. Windows sometimes only py. This is the whole disease.

  Bug 2: calling pip binary directly. Fragile everywhere. Cave law: never call 
  pip, always <python> -m pip. Kills entire class of pain.

  Fix = resolve system python once, use venv python for everything after:

  # system python — only job is creating the venv
  SYSPY := $(shell command -v python3 || command -v python || echo py)

  ifeq ($(OS),Windows_NT)
  PY := .venv/Scripts/python.exe
  else
  PY := .venv/bin/python
  endif

  then in setup:

  $(SYSPY) -m venv .venv
  $(PY) -m pip install --upgrade pip
  $(PY) -m pip install -r services/requirements.txt

  After venv born, $(PY) same beast on every machine — no more guessing. PIP :=
  variable dies, worker target already uses $(PY), stays happy.

  Why not two files: run.ps1 already exists as Windows twin. Add ubuntu.sh =
  three copies of same brain. Every new target = edit three places, someone
